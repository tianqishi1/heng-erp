# AI 原生 ERP 产品设计方案（代号：衡 ERP / HengERP）

> 版本 v0.1 ｜ 2026-11-23 ｜ 承接《开源 ERP 可行性评估》路线 C：AI 原生 + 中国财税合规 + open-core。

> 配套文档：《AI原生ERP技术实现方案.md》

## 1. 产品定位

**一句话**：为 AI 从头设计的开源 ERP——"确定性业务内核 + 业务语义层 + Agent 运行时"三层架构，让 AI 与人在**同一套权限、审计、事务平面**上操作企业业务，开箱即带中国财税合规。

**与"AI 增强型 ERP"的本质区别**（Odoo 19/20、金蝶灵基都是在旧架构上加 AI）：

| 维度 | AI 增强型（现状） | AI 原生（本产品） |
|---|---|---|
| AI 的位置 | 侧边栏插件、字段级 OCR/摘要 | Agent 是一等公民，与人类用户同权同审计 |
| 数据模型 | 面向表单/报表 | 面向语义：实体自带含义、单位、口径、血缘、敏感级 |
| 业务操作 | UI 按钮 + API | 统一 Action 契约：强类型、幂等、可 dry-run、可被 Agent 调用 |
| 质量保障 | 功能测试 | 评测驱动：每个 Agent 能力自带 eval 集与回归门禁 |
| 演进方式 | 年度大版本 | 受控自进化：prompt/知识/策略按周演进，内核只走工程发布 |
| 二开方式 | 写代码模块 | 提交元数据包 + 评测集，AI 辅助生成，升级兼容有契约 |

**六条设计原则**（所有产品/技术决策的裁决依据）：

1. **确定性内核，概率性外围**：钱、库存、税、凭证由确定性引擎执行；LLM 只做理解、规划、起草、解释，**永远不直接写账**。
2. **一切业务操作皆 Action**：人和 Agent 走同一条校验→规则→事务→事件→审计管线，AI 能做的事人一定能做、能审、能回滚。
3. **语义优先**：先建业务本体与指标口径，再谈自然语言交互；NL→结构化查询走语义编译，不做裸 text2sql。
4. **合规即代码**：税率、发票、申报规则是版本化、带生效日期的规则包，政策变更=发布规则包+全量回归。
5. **评测驱动开发**：没有 eval 集的 Agent 能力不上线；财务结果的评测用精确断言，不用 LLM 打分。
6. **可进化但受控**：自进化只发生在"沙箱→评测→人审→灰度→可回滚"闭环内，进化对象是外围资产，不是内核。

**不做什么**：不做大企业项目制交付（用友三年亏 44 亿的教训）；不在 MVP 做集团合并/复杂 MRP；不做通用聊天助手；不承诺"无人化财务"。

## 2. 目标用户与场景

### 2.1 用户分层

| 层 | 角色 | 核心诉求 | 产品给什么 |
|---|---|---|---|
| 决策购买者 | 中小企业老板/总经理（50–2000 人） | 少雇人、不出错、看得清 | 经营日报 Agent、自动化率报表、风险巡检 |
| 日常使用者 | 销售/采购/仓管/会计 | 少录单、少对账、少加班 | 对话式开单、AI 记账建议、月结助手 |
| 生态开发者 | ISV/实施伙伴/企业 IT | 二开能赚钱、升级不被坑 | 元数据二开框架、应用市场、API 兼容契约、评测基建复用 |
| 运维管理者 | 企业 IT / 我们的 SRE | 可控、可查、可回滚 | 信任控制台、决策回放、SLO 看板、进化审批 |

### 2.2 三个典型画像

- **贸易公司会计"王姐"**（45 岁，用了 15 年某蝶 K3）：不信任 AI 碰账。产品策略：AI 只出"记账建议卡"，她一键采纳/驳回，每次驳回都变成评测用例；三个月后她的重复录入下降 70%，但每笔凭证仍由她确认。
- **离散制造厂老板"陈总"**（38 岁，200 人厂）：要的是"别让我养 3 个统计员"。产品策略：库存巡检 Agent 每天 7 点推送异常（呆滞、缺料、账实差异），附证据链与处理建议，一键下发任务。
- **实施伙伴"张工"**（30 岁，Odoo 出身）：靠二开吃饭。产品策略：行业包=元数据+规则+评测集，官方承诺 N-2 升级兼容与迁移编译器，市场抽成 25%，他的资产跨客户复用。

### 2.3 五个核心场景（Before / After）

| 场景 | Before（传统 ERP） | After（衡 ERP） |
|---|---|---|
| 销售开单 | 翻客户档案→查上次价格→录 8 个字段→算税 | 一句话"给华东李总发 200 台 A100，按上次价，含税"→Agent 生成订单草稿卡（含价格来源、税额计算过程）→人确认→落库 |
| 采购对账 | 会计逐行勾稽发票/入库单，2 天/月 | 对账 Agent 自动三单匹配，差异分级：无差异自动过（L2）、有差异出证据卡给人 |
| 月结 | 财务加班一周，checklist 靠人盯 | 月结 Agent 按 checklist 驱动：试算平衡→折旧→结转→报表，每步出断言结果，异常自动定位到单据 |
| 经营分析 | 导 Excel 做透视表 | "上月华东区毛利为什么降了？"→语义层编译指标查询→Agent 给出数字+归因+单据证据链 |
| 政策变更 | 会计手工改税率、出错补申报 | 官方发布"2027 税率规则包"，带生效日期与回归评测，租户一键升级 |

## 3. 产品形态与信息架构

### 3.1 双通道交互（产品的心脏）

- **通道 A：传统工作台**——表格/表单/看板/审批流，100% 功能可脱离 AI 使用。**AI 全挂时 ERP 必须完整可用**（这是企业客户的底线信任）。
- **通道 B：Copilot + Agent**——全局命令栏（Ctrl+K）、侧边对话、单据内嵌"让 AI 填"、语音（V2）、定时/事件触发的后台 Agent。
- 两通道**共用同一 Action API 与权限模型**：不存在"AI 专用后门"。每个 Agent 动作在 UI 上呈现为**行动卡**：意图、参数、证据、影响预览（dry-run）、风险级、回滚点、审批人。

### 3.2 Agent 角色矩阵与自动化分级

每个 Agent = 职责 prompt + 工具集（Action 白名单）+ 策略 + **专属评测集** + SLO。

| Agent | 职责 | 默认级别 | 可升级到 |
|---|---|---|---|
| 开单员 | 对话/邮件/截图→单据草稿 | L1 建议 | L2（老客户老 SKU 复购单） |
| 对账会计 | 三单匹配、银行流水勾稽、记账建议 | L1 | L2（无差异匹配自动过账） |
| 库存巡检员 | 呆滞/缺料/账实差异巡检与告警 | L2（只读+通知） | L3（自动生成补货建议单） |
| 税务合规官 | 开票校验、税率适用、申报前检查 | L1 | L2（校验类自动执行） |
| 采购分析员 | 价格异动、供应商比价、交期预警 | L2（只读） | — |
| 月结助手 | checklist 驱动月结流程 | L1（逐步确认） | L2（低风险步骤自动） |

**自动化三级**（租户可按 Agent×动作粒度配置）：
- **L1 建议**：AI 起草，人审批后执行。默认级别。
- **L2 条件自动**：白名单动作+金额/数量阈值+事后抽审。升级条件：该场景评测分≥95 且生产一次通过率≥98% 连续 4 周。
- **L3 自治**：限定只读/通知/草稿域（巡检、报告、提醒）。**资金支付、红字发票、改价、删单永远不进 L3，强制四眼审批。**

### 3.3 信息架构

`工作台（按角色） / 业务域（销售·采购·库存·生产·财务·税务） / Agent 中心（矩阵·任务队列·行动卡收件箱） / 经营分析（语义 BI） / 信任控制台（审计·回放·评测看板·进化审批·自动化分级） / 开发者中心（元数据·沙箱·市场） / 设置（组织·权限·模型与配额·规则包）`

## 4. 核心用户旅程

### 4.1 Onboarding（目标：30 分钟出第一张 AI 草稿单）

1. 建租户→选行业模板（贸易/离散制造/电商）→自动初始化科目表、税制、单据流、评测沙箱。
2. 导入客户/商品/期初库存（Excel 模板 + AI 字段映射，映射结果人工确认）。
3. 连接数电票（税务 UKey/电子税局授权）与银行流水（导入或直连）。
4. 引导完成第一句话开单→看到行动卡→确认→打印/开票。**首次价值体验必须落在"真实单据"上，不是聊天 demo。**

### 4.2 每日主循环

`早 7:00 巡检 Agent 推送异常日报 → 白天：人处理业务，Agent 起草/校验/匹配，行动卡收件箱按风险排序 → 晚：对账 Agent 跑当日勾稽 → 每周五：经营周报 + AI 质量周报（自动化率、升级率、成本）`

### 4.3 一句话开单（核心时序，与技术方案 §6 对应）

`用户话语 → 意图/实体解析（语义层） → 生成 Plan（动作序列+前置条件） → 逐步 dry-run（价格来源、信用额度、库存可用量） → 行动卡（含证据与影响预览） → 人确认 → Action 管线（校验→规则→事务→Outbox 事件→审计） → 回执+可回滚点`

### 4.4 月结旅程（财务信任的建立过程）

`月结 Agent 生成 checklist（含每步断言） → 逐步执行：试算平衡/往来核对/折旧/结转 → 每步展示精确断言结果（借=贷、账=实） → 异常步骤定位到具体单据并给修复建议 → 会计确认关账 → 出报表 → 全程决策留痕可回放`

## 5. 功能模块设计

### M1 平台内核与低代码（社区版）
元数据驱动的实体/动作/规则/视图定义；可视化表单与列表设计器；审批流编排（人任务+Agent 任务同编排）；组织/角色/数据权限；审计日志。**二开=改元数据，不是 fork 代码。**

### M2 供应链（社区版）
销售（报价→订单→出库→开票）、采购（申请→订单→入库→对账）、库存（多仓/批次/序列号/盘点/调拨）、基础 MRP（V1）。所有单据原生支持"AI 起草+人确认"与事件订阅。

### M3 财务与税务合规（基础社区版 / 深度企业版）
- 社区版：总账、应收应付、出纳、固定资产、CAS 科目表、三大报表、**数电票开具/查验/入账**。
- 企业版：成本核算（移动加权/标准成本）、纳税申报直连、银企直连、多组织/合并报表、全面预算。
- 合规规则包：税率/发票规则/申报口径版本化，带生效日期，官方维护+评测回归（这是相对 Odoo 的核心差异化，也是持续成本，必须订阅化）。

### M4 Agent 运行时与矩阵（框架社区版 / 高级能力企业版）
社区版：Copilot（开单/查询/解释）、行动卡、L1 审批、基础评测集。
企业版：全部 Agent 矩阵、L2/L3 自动化、语音、邮件/截图多模态起草、组织记忆、模型私有化路由。

### M5 语义 BI（社区版基础 / 企业版归因）
指标注册中心（口径唯一）、自然语言→语义编译查询、经营日报/周报 Agent、归因分析（企业版，附证据链）。**杜绝"AI 编数字"：所有数字可点开看 SQL 口径与单据来源。**

### M6 二开平台与应用市场（开发者生态）
ISV 包格式（元数据+沙箱代码钩子+评测集+迁移脚本）；AI 辅助生成模块（描述业务→生成元数据草稿+测试）；沙箱租户工厂；市场签名/审核/抽成 25%；**升级兼容契约：API N-2 兼容 + 迁移编译器 + 升级 rehearsal 工具**（直击 Odoo 社区版升级无官方工具的最大痛点）。

### M7 信任控制台（企业版，可观测/可评测/自进化的产品化）
- 审计与回放：任一 AI 动作的完整决策链（prompt 版本、模型、证据、工具序列、审批人）。
- 评测看板：各 Agent 评测分趋势、生产一次通过率、人工升级率、漂移告警。
- 进化审批：每周"进化 PR"列表（diff+评测报告+风险评级），一键批准/驳回/回滚。
- 自动化分级管理：按 Agent×动作配置 L1/L2/L3 与阈值。
- 成本与配额：租户/Agent 级 token 与费用预算。

## 6. 关键交互与信任设计

1. **行动卡**：意图一句话 + 参数表 + 证据链（引用单据/规则/历史价格）+ 影响预览（dry-run 的库存/余额/税额变化）+ 风险色标 + 确认/修改/驳回。驳回必须选原因（结构化），直接进评测用例池。
2. **证据链强制**：AI 的每个结论必须可点开溯源；无证据的回答显式标注"推测"。
3. **置信度与升级**：低置信→不猜，转人工并说明缺什么信息；每租户有"不确定性预算"，超预算自动收紧自动化级别。
4. **四眼原则**：资金支付、红字发票、价格主数据、删单：AI 起草→人 A 复核→人 B 批准，全程留痕。
5. **时间机器**：业务状态快照 + Agent 决策回放；任何自动化动作有一键补偿（补偿本身也是注册 Action）。
6. **AI 质量周报**：给老板看"AI 干了多少活、错了几次、省了多少钱"，把信任变成可度量的资产。

## 7. 社区版 / 企业版切分（open-core）

| 层 | 社区版（LGPLv3，允许 ISV 闭源模块） | 企业版（专有订阅） |
|---|---|---|
| 内核 | 完整平台内核+低代码+审计 | 高可用托管、多组织、字段级加密、国密 |
| 业务 | 进销存+基础生产+**完整基础财务**（不学 Odoo 锁会计） | 成本核算、合并报表、预算、银企直连 |
| 合规 | 数电票开/查、基础税制 | 申报直连、政策规则包订阅、税务风险巡检 |
| AI | Copilot L1+行动卡+基础评测 | Agent 矩阵、L2/L3、组织记忆、私有化模型、信任控制台 |
| 生态 | 二开框架+沙箱+市场接入 | 官方升级迁移工具、伙伴认证、专属支持 |

商业原则：开源部分"真能用"（完整业务闭环），商业部分卖**规模、合规、AI 深度、省心**；预留 CLA 双许可能力；商标条款防云厂商白嫖。

## 8. 指标体系

**北极星**：WAA（Weekly Successful Agent Actions）——每周由 Agent 完成且一次通过的业务动作数。它同时捕获价值量与质量。

| 类别 | 指标 | 目标（V1） |
|---|---|---|
| 价值 | 单据 AI 起草占比 | ≥60% |
| 价值 | 对账/巡检自动化率 | ≥80% |
| 质量（护栏） | AI 致错单率（人审后口径） | <0.1% |
| 质量 | 行动卡一次通过率 | ≥90% |
| 质量 | 人工升级率 | <15% 且趋势下降 |
| 体验 | Copilot 首 token P95 | <2.5s |
| 商业 | 租户 AI 月成本/毛利 | 成本<订阅收入 15% |
| 生态 | 市场 ISV 包数 / 复用率 | V1 ≥50 个 |
| 进化 | 每周进化 PR 采纳率 / 回滚率 | 采纳≥60%，回滚<5% |

## 9. MVP 范围与路线图

### MVP（0–6 个月，15 人）——验证"AI 开单+合规记账"单点闭环
范围：M1 内核、M2 进销存、M3 基础财务+数电票、M4 Copilot（开单/查询/解释，仅 L1）、M7 最小审计+评测基建、3 个行业模板中的贸易模板。
**Go/No-Go（第 6 个月）**：3 家灯塔客户付费试用；行动卡一次通过率≥85%；AI 致错单率<0.3%；单租户 AI 成本<¥800/月。达标→V1；不达标→收缩为"AI 单据中间件"（路线 D）止损。

### V1（6–18 个月，25–35 人）——可售卖的 open-core 产品
完整财务+税务规则包订阅、Agent 矩阵 L2、语义 BI、二开平台+市场 beta、信任控制台、企业版正式收费、信创数据库（openGauss）适配。
**决策点（第 18 个月）**：付费客户≥30 家、ARR≥¥500 万、ISV 伙伴≥10 家、评测回归全绿。

### V2（18–36 个月）——平台化与自进化 GA
集团多组织/合并、银企直连、MRP 深化、信创全栈（达梦/麒麟/国密）、自进化流水线 GA、行业包（离散制造/跨境电商）、语音与多模态。

| 伙伴认证 | ¥15,000/年 | 培训+认证+线索分发 |

单位经济测算：200 用户中型租户，月 5,000 Agent 动作×均 8k token≈4,000 万 token，混合路由（云大模型+私有小模型）成本约 ¥300–800/月，对 ¥4–8 万/月订阅收入，AI 毛利健康。**成本可控的前提是模型路由与缓存（技术方案 §7）。**

## 11. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 财务 AI 出错摧毁信任 | 高 | 确定性内核+L1 默认+四眼+精确断言评测；错单率作为发布门禁 |
| 合规维护成本失控 | 高 | 规则包产品化订阅化，政策变更=规则包发布+回归，边际成本递减 |
| 生态冷启动（鸡生蛋） | 高 | 先自营 3 个行业模板打样；完整财务开源吸引 Odoo 实施商迁移；升级兼容契约作为迁移卖点 |
| 大模型成本/供应波动 | 中 | 多供应商路由+私有小模型兜底+按动作计费转嫁可预期 |
| 自进化引入回归 | 中 | 进化只动外围资产、评测门禁、灰度+自动回滚、每周限额（技术方案 §13） |
| 巨头跟进（金蝶灵基/Odoo AI） | 中 | 差异化在"开源+二开生态+AI 原生架构"，不在单点 AI 功能；保持架构代差 |
| 提示注入/数据泄露 | 高 | 工具最小权限、外部内容指令隔离、敏感字段私有化路由、租户隔离渗透测试 |

## 12. 待决策问题（下一步）

1. 内核语言：Python（本方案默认，AI 生态+元数据引擎开发速度）vs Java（国内 ISV 人才池）——按创始团队基因定，见技术 ADR-01。
