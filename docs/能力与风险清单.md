# 衡 ERP · 系统能力清单与变更点 / 不确定项 / 风险清单

> 2026-11-23 · M1 版本。业务语言描述系统能做什么、改了什么、哪些没定、哪些有风险。

---

## 一、系统现在能做什么（业务视角）

| 能力 | 说明 | 在哪里用 |
|---|---|---|
| 登录与角色 | 账号密码登录；老板/财务/审批人/销售四种角色，权限各不相同；**审批人=登录账号，不可冒充** | 登录页 |
| 一句话开单 | "给华东李总发200台A100，按上次的价格，含税"→自动找客户、取上次价、算税→待确认卡片→人确认才建单 | 工作台 |
| 同名客户不瞎猜 | 两个"李总"时反问让你选 | 工作台 |
| 订单全流程 | 新建→确认出库（自动扣库存+自动记账）→开票→收款→取消（自动红冲+回补库存） | 销售订单页 |
| 价税自动分离 | 精确到分；税率按业务日期适用当年政策（2019/2026 双版本可复现） | 全局 |
| 开票（演示通道） | 税额与订单自动勾稽；未接真实税务平台 | 订单行"开票" |
| 收款双人审批 | 两位**不同登录账号**先后批准才执行；同一账号批两次被拒 | 审批中心 |
| 审批中心 | 业务摘要+风险等级+审批进度（1/2 人） | 审批中心 |
| 经营问数 | 数字+统计口径+单据下钻，不是 AI 编的 | 工作台 |
| 账务体检 | 订单勾稽/借贷平衡/账实一致/发票勾稽 四项持续校验 | 账务体检页 |
| **系统自进化** | 自动发现"听不懂的话"→生成改进候选→沙箱全量评测→人审→灰度→全量/回滚（详见第六节） | 进化中心 |
| **扩展包** | 不改核心代码，安装元数据包即获得新字段/新动作（示例：订单优先级）；每个扩展动作强制带评测集 | 扩展与设置页 |
| 全程留痕 | 每笔操作记录谁做的、依据什么；AI 决策可回放 | 后台接口 |
| 信用控制 | 超信用额度直接拒绝并提示 | 新建订单时 |
| AI 断了也能用 | 助手不可用时全部表单/审批功能不受影响 | 全局 |

## 二、现在还不能做什么（边界）

- 没采购、MRP/生产、HR、固定资产、成本核算、合并报表、纳税申报直连、银企直连。
- 发票是演示通道；智能助手当前为离线规则模板兜底（真实大模型接口已就位，配置即启用，约束不变）。
- 数据库为 SQLite 演示库（生产路径 PostgreSQL+行级隔离已备好）；单机单进程。
- 界面为增强版演示工作台（最终产品 UI 为 React+AntD 元数据渲染器，M2）。
- 密码为加盐 SHA256（演示级），生产需 Argon2/SSO；会话 12 小时。
- 自进化 M1 仅覆盖"话术模式"资产；知识/路由/记忆进化与 LLM 辅助候选生成在 M2。

## 三、变更点（M1 相对 M0）

1. **登录鉴权+角色权限**：所有业务接口需登录；审批人身份绑定登录账号；进化审批/扩展包安装仅老板角色；财务/销售越权返回 403。
2. **自进化流水线 alpha**：案例挖掘（只挖"暂不支持"类升级，消歧反问属正确行为不挖）→确定性候选生成→沙箱黄金集全量评测（零退化门禁）→进化单（含 diff+评测报告）→人审→本租户灰度→全量/一键回滚。护栏：每周≤10 单、同资产 72h 冷却。
3. **扩展包机制**：元数据 overlay（只叠加、禁改官方字段）+通用字段处理器+强制评测集；安装即生效并留痕；示例包 trade_priority（订单优先级）。
4. 界面：登录页、进化中心、扩展与设置页、订单优先级展示与设置；四眼审批改为真实账号切换。
5. 工程：订单表扩展字段容器 ext+轻量迁移；审批执行使用审批人真实权限（不再默认全权）。

## 六、自进化是怎么回事（给非技术读者）

**它能自己发现什么**：用户说了系统听不懂的话（如"帮王总订50个B200"），助手会转人工并**自动记下这条案例**；人工驳回也会进案例池。

**它怎么改自己**：在"进化中心"点"生成候选"，系统提出一个话术改进方案，然后**先在沙箱里把全部 17 个黄金评测用例重跑一遍**——任何一个财务断言退化都直接否决；新说法也必须真的能用。通过的方案成为一张"进化单"，附变更内容与评测报告。

**谁说了算**：人（老板角色）批准后才生效，且先只在当前租户"灰度"试用；确认没问题再全量；任何时候可一键回滚到上一版本。

**它永远不能改什么**：账务逻辑、税率规则、权限、审批策略、内核代码——这些只能走人工工程发布。每周最多 10 张进化单，同一资产 72 小时冷却，防止"越改越乱"。

**演示路径**：工作台说"帮王总订50个B200，单价1200"（听不懂）→ 进化中心"挖掘优化点"→"生成候选"（看评测报告）→"批准并灰度"→ 回工作台再说一遍（能开单了）→"全量发布"或"回滚"。

## 七、扩展性是怎么回事（给开发者/实施伙伴）

- 扩展=提交**元数据包**（新字段/新动作/新规则/视图）+**评测集**，不 fork 核心代码。
- 官方字段禁改（overlay 校验强制）；新动作必须带评测集才能注册；安装留痕。
- 示例：`metadata/extensions/trade_priority`（订单优先级字段+设置动作，走统一 Action 管线/审计/权限）。
- 升级兼容契约（N-2+迁移编译器）与 ISV 市场在 M2；当前已可手工安装 bundled 包演示完整机制。
